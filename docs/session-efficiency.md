# 续接效率与可读询问

2026-10-21 对本机近期的 Bridge 请求做只读审计：一次手动排查会话中约六分之一的请求重新发送了全部历史，这些重建累计重复发送了数十万字符的相同工具结果。旧日志没有前缀差异诊断，不能把这些重建都归咎于同一个原因，也不能把历史重写、压缩或切换模型的必要重建算作可安全删除的重复。

## 本次修复

- 首次模型请求带完整协议；同一 Qoder 会话的后续增量只带简短续接说明，继续遵守已有协议。工具选择始终显式保留；工具 schema 改动仍完整发送，未改动的 schema 不重复压缩或发送。
- Host 回传的第一条 assistant 工具调用如果与刚刚校验通过的决策逐个同名、参数对象完全相同、批次数相同，且没有其它内容或未知字段，只发送新分配的工具 ID、名称和参数哈希；完整参数已存在于同一模型会话。仅在这样确实更短时去重。后续真实工具结果原样保留，参数改动、其它调用或新会话都不适用。
- 会话前缀按实际发送给决策模型的消息表示比较。不把未发送的 reasoning/本地传输元数据变化当作历史改写；角色、正文、工具 ID、工具参数或命名变化仍会使前缀不匹配。不会用忽略真实历史变化的方式强行复用。
- `context_transport.optimization` 记录协议复用与省去的参数字符数。`context_transport.reset` 记录历史缩短/改写、首个变化位置、角色、数量和 SHA-256，不复制正文。Bridge 重启、会话淘汰或真正历史改写仍可能需要重新发送完整上下文。

这减少传输和累计模型上下文，不承诺真实推理时长或账号费用按同一比例降低。缓存仍按既有来源标记；SDK 报告 Credits=0 不证明账户没有计费。未改用户选择的模型、窗口和 effort；未扩大推理守卫、纠错次数或期限。

## 不把工具协议显示为回答

实际日志中出现过畸形的 `<system_call><name=...>` 原始回复，旧版误判为纯文本 final。现在识别这种协议意图并拒绝整批，进入原有最多两次的请求内纠正；不能猜补参数或执行半批。即使模型把这段坏输出包装进 final.content，也不会先流给 DSH。

需要用户选择时，使用 DSH 声明的 `ask_user_question` schema，或给出自然语言回复。JSON 字符串中的一般 XML 示例与文件工具参数仍作为数据保留。离线验证使用了本机记录的坏输出、DSH 问题 schema 和本机 pi-ai 适配器；仓库测试只含合成样例。模拟重生成通过不等于真实上游模型恢复率。

## 边界

本次修复只涉及 Bridge 自身的上下文传输与决策解码。DSH 中其他模型提供商的上游拒绝（例如渠道校验未通过）不在 Bridge 范围内，Bridge 不能解除，需要按服务方支持的接入方式处理。

审计报告保存在本机 `reports/`，不进入仓库。

## 中断后的部分用量与新格式回放（2026-10-21）

新增日志显示增量续接和参数去重正常工作；剩余的明显慢点集中在少量长推理守卫和格式重新生成。本次没有提高守卫/输出预算，也没有擅自修改用户选择的模型、窗口或推理等级。

推理守卫有时在收到输入上下文占比前中断，因此该次输入 token 不可知。旧的全量求和会使整条 HTTP 请求的 `normalized_usage` 为 null，连已经收到的输出/推理计数也在汇总中被省略。新增 `telemetry.usage_accounting` 分开保留可用的输入、输出、推理小计、每一维的未知覆盖数和来源：输入未知不会抹掉可信流增量计数，缺失值也不会被补成零。未通过流粒度检查的计数不会当作 token 使用。

`normalized_usage` 继续表示所有尝试的累计消费；不能确定完整输入时仍为 null。`client_usage` 继续使用**最后一次尝试**的输入上下文与本请求所有可计量输出，不用较早尝试的旧输入替代最后一次未知上下文。分维度账本的输出估计只覆盖已收到的流式增量，不保证取消后的上游实际生成量或账户账单。

`metrics` 增加明确的 known token 小计与未知请求数，缺失完整覆盖时总量为 null。`tasks:report` 使用同一计量口径，分别显示 HTTP 请求、已知模型调用数和未知调用计数，并保留部分已知 Credits；不能再把一次带纠错的 HTTP 请求当成精确的一次模型调用。

另外只兼容一种原始日志中已确认的包装错误：一个调用已完整关闭后，下一调用的**显式工具名**开标签多了 `/`。仅在整个批次完整、有唯一提供工具、每个调用有完整结束边界时去掉该斜杠；参数文本不变，全部调用仍通过真实 schema 校验。缺少名称/字段、未知名称、未闭合范围和不完整批次仍拒绝，不从参数推测新工具名。JSON 和字符串内的标签保持为数据。

离线重放使用原会话持久化的真实工具 schema 与原始响应，逐个对比独立解析后的参数哈希；没有执行应用工具或新建付费模型探针。历史日志保持原样，不能凭新字段反向编造旧日志缺失的用量。

## 参数正文与混合响应计数（2026-10-22）

当一个关闭标签还显式携带下一参数的名字时，解析器须先读取下一参数的完整值，再判断调用结束。下一参数正文中的 `｜｜DSML｜｜ invoke>` 是数据，不能用来提前结束 edit/write。原有完整裸结束标记及扁平 kind/name 包装兼容继续受 schema 与整批校验约束。

流式响应与最终 assistant 记录不是相互包含的集合。`model_requests` 改为按 message ID 与 request ID 建立关联去重，兼容只有流事件的中断响应、只有 assistant 的重试响应，以及同一请求的重复记录。仅有不够关联的标识、无标识流事件或互相冲突的 ID 时，完整计数保持未知，`model_requests_known` 与恢复记录的 `knownModelRequestsSubtotal` 保留已确认小计。计数来源写入任务日志；恢复尝试合计与本地重放不会重复累计小计。
