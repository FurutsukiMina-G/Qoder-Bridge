# 本地 DSH 发现：禁止对无关端口进行 HTTP 探测

## 反馈与核查范围

2026-10-21 收到使用者反馈：一个每分钟运行的自定义自动续接计划任务（脚本 `scripts/auto-continue.mjs`）在发现服务时，向另一个程序（游戏客户端）的二进制 IPC 监听端口发送了 HTTP，该程序随后报错。这是应修复的发现方式；反馈中的因果与时间关联尚未独立复现。

当前仓库及其历史中没有该 `auto-continue.mjs`，维护者机器上也没有对应的计划任务。不能断定它来自某个正式版本，也不能据此修改或停用反馈者的任务。需保留原脚本、版本/提交和任务操作信息，再核对它是否为早期分发件或使用者扩展。

现有 `scripts/dsh-rpc.ts` 不扫描本机全端口，但旧流程会先请求缓存地址、或先访问启动日志里的 token URL。旧地址被其它程序复用时同样可能误发 HTTP，因此本次一并加固。

## 修复后的规则

1. 候选地址只来自本项目缓存和指定的 DSH 启动日志；不新增端口范围、全端口扫描或“未知服务先请求再识别”的回退。
2. **任何 HTTP、登录 token 或 Cookie 发送之前**，先只读查询 Windows 进程表和 TCP 监听表。标准桌面端须同时匹配 DSH desktop host 的确切脚本参数、桌面进程父子关系、安装目录内的可执行文件和监听 PID。仅名为 Node、DeepSeek 的进程或桌面进程的其它子进程都不够。
3. 缓存、日志和已经连接过的地址全部适用；每次请求重新核对，检查期间 PID 被复用也拒绝。不能核实归属就失败，不通过 HTTP 来猜测服务身份。
4. 已核实的地址也禁止自动跟随 HTTP 重定向，避免向另一个本地服务发送后续请求。
5. 自定义 CLI 宿主可显式配置绝对路径 `DSH_HOST_ENTRY`，值必须是该宿主真实的 JS 入口，并作为独立命令行参数出现。它不是任意 `node.exe` 的放行开关。非 Windows 平台暂时明确失败，不回退成端口扫描。

端口元数据查询是只读 OS 查询，不会建立到那些端口的连接。CLI 应从仓库根目录运行，并有读取本用户进程/监听元数据的权限。读取失败时应检查运行上下文和 DSH 启动日志，不应改 ACL 或扩大探测范围。

## 自动续接扩展的迁移

拿到旧版/自定义 `auto-continue.mjs` 后，应删除其通用端口枚举与 HTTP 猜测逻辑，保留业务上的续跑和停止边界，改用同一受保护的公开 RPC 入口。位于仓库 `scripts/` 下的扩展可在构建后这样导入：

```javascript
import { rpc } from '../dist/scripts/dsh-rpc.js';
const sessions = await rpc('session/list', { _request: {} });
```

任务的工作目录须为仓库根目录。不要另外实现“上述方法失败就遍历其它端口”的回退；单独换一个固定端口也不能防住旧缓存的端口复用问题。

反馈者若仍在遇到报错，可先确认该计划任务确实指向问题脚本，再临时停用**这一项自动续接任务**；这会暂停自动续跑。修复脚本并验证没有误探测后再恢复。当前修复没有自动修改任何人的计划任务。

## 验证

`tests/dsh-endpoint.test.ts` 包含：标准 DSH 的正确识别；不信任 GPU/普通 Node/其它程序；错误或被复用的缓存端口；元数据读取拒绝；跨端口重定向；自定义 CLI 的确切入口验证。

关键回归使用本机模拟的二进制 IPC 服务：不发送任何 HTTP 即拒绝错误端口，断言该服务收到 **0 个连接、0 字节**。没有为了复现而向真实游戏端口发送 HTTP。另有实际 DSH 的只读 `settings/describe` 验证，证明正常连接仍能通过。

本地验证记录保存在本机 `reports/`，不进入仓库。这些结果不等于反馈者的未知脚本已升级或其机器已复测通过。
